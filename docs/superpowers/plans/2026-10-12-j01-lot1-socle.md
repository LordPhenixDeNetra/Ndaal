# J01 lot 1 — Socle du dépôt : plan d'implémentation

> **Pour les agents :** sous-compétence requise : superpowers:subagent-driven-development (recommandée) ou superpowers:executing-plans, tâche par tâche. Les étapes utilisent des cases à cocher (`- [ ]`).
>
> **Pas d'étape de commit** : le responsable du projet commite lui-même (`CLAUDE.local.md`). À la fin du lot, on lui donne les commandes git (`cmd`, `git commit -s`, un commit par tâche).

**Objectif :** poser le workspace Cargo des 26 crates, les versions figées, les contrôles d'hygiène, `cargo deny` et les fichiers communautaires, tout vérifiable en local avant la CI (lot 2).

**Architecture :** un workspace Cargo (`crates/*`) avec métadonnées et lints centralisés. Les contrôles d'hygiène sont écrits en Rust dans une crate outil `xtask/` (sans dépendance, testable par `cargo test`, identique sous Linux, macOS et Windows), appelée par de courts scripts `scripts/*.sh`. La vérification du code propre à Linux tourne dans le conteneur Rust figé.

**Pile :** Rust 1.99.0, édition 2024, Cargo (resolver 3), `cargo-deny`, Docker, Bash (Git Bash sous Windows).

**Spécification :** [CAHIER_DES_TACHES.md, J01](../../../CAHIER_DES_TACHES.md#j01--fondations-du-projet) (T01.01, T01.02, T01.16, T01.19, T01.25), [ARCHITECTURE.md §3](../../../ARCHITECTURE.md#3-organisation-du-code), [CLAUDE.md](../../../CLAUDE.md) §3, §4.3, §4.6, §4.7, §4.12, §11.

## Contraintes globales

- Rust **1.99.0** exactement, édition **2024**, `rust-version = "1.99"` (décision D-01 du 2026-10-12).
- Licence **Apache-2.0** pour toutes les crates ; dépendances autorisées : MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, Zlib, Unicode-DFS-2016, MPL-2.0 ; interdites : GPL, AGPL, SSPL, BSL, non libres (C-02).
- `#![forbid(unsafe_code)]` dans toutes les crates **sauf** `ndaal-io`, `ndaal-runtime`, `ndaal-vector`, `ndaal-wal` (ARCHITECTURE §3).
- Fichiers `.rs` : ≤ 800 lignes (1 500 pour les tests), fonctions ≤ 100 lignes, ≤ 7 paramètres, largeur 100 colonnes (CLAUDE.md §4.6).
- Aucun emoji dans le dépôt ; ASCII seulement dans `.rs`, `.toml`, `.yml`, `.yaml` ; LF, pas d'espace en fin de ligne, saut de ligne final (CLAUDE.md §4.7).
- Aucune dépendance externe dans ce lot (`[workspace.dependencies]` reste vide) : la bibliothèque standard suffit.
- `publish = false` partout tant qu'aucune publication n'est décidée (CLAUDE.md §13).

## Prérequis sur le poste (à faire une fois, pas versionné)

Le dépôt est dans OneDrive. Un dossier `target/` de plusieurs Gio y serait synchronisé en permanence et OneDrive verrouillerait des fichiers pendant la compilation (erreurs « Accès refusé »). Avant la tâche 1 :

```cmd
setx CARGO_TARGET_DIR "C:\cargo-target\ndaal"
```

puis rouvrir le terminal. Le `.gitignore` garde `/target/` pour les autres postes.

## Points à surveiller en revue

1. **Chemins avec espaces et accents** (`N:\OneDrive - Université …`) : `check-linux.sh` doit monter le dossier dans Docker correctement depuis Git Bash. Testé à la tâche 2, étape 6.
2. **Fichiers à fins de ligne CRLF ou sans saut de ligne final** déjà présents dans l'arbre : `hygiene` doit les signaler avec le chemin et le numéro de ligne, pas seulement un échec global. Testé à la tâche 3.
3. **Exceptions de taille** (code généré `*_generated.rs` ou sous `generated/`, fichiers de tests) : elles doivent passer, sinon les futurs fichiers générés bloqueront la CI. Testé à la tâche 3.
4. **Fichiers binaires** suivis par git (images, futurs corpus de fuzzing) : `hygiene` ne doit ni planter ni les signaler. Testé à la tâche 3.
5. **Crate exemptée qui perd son exemption** : si `ndaal-io` ajoute `forbid(unsafe_code)`, rien ne casse ; mais une crate non exemptée sans `forbid` doit être signalée. Testé à la tâche 3.

**Interfaces :**
- Produit : `cargo run -p xtask -- hygiene` (code de sortie 0 si aucun problème, 1 sinon, une ligne par violation `chemin:ligne: règle: détail`), appelé par `scripts/check-hygiene.sh` (`exec cargo run --quiet -p xtask -- hygiene "$@"`).
