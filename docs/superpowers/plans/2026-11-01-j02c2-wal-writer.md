# J02-C2 — Écrivain du journal, fichiers et modes : plan d'implémentation

> **Pour les agents :** sous-compétence requise : superpowers:executing-plans, tâche par tâche.
>
> **Pas d'étape de commit** : le responsable commite sur une branche `j02c2-wal-writer`, puis ouvre une demande de fusion. Le compte rendu donne les commandes git et le contenu du formulaire de demande de fusion.

**Objectif :** livrer l'écrivain du journal par shard :
- écriture groupée avec un seul vidage en cours ;
- fichiers préalloués, recyclés et repris sans risque ;
- modes `none`, `async` et `sync` ;
- en-tête de trame de 44 octets, avec deux CRC ensemencées.

**Architecture :**
- `WalWriter<D: Disk, C: Clock>` vit sur le cœur du shard (`Rc`, sans verrou).
- `open` rend l'écrivain et sa tâche de vidage (`Flusher`) ; c'est l'appelant qui lance cette tâche : le runtime du cœur, ou `Sim::spawn`.
- Les E/S passent par le trait `Disk` : `PoolDisk` de classe `Critical` en réel, `DeviceDisk` en simulation.

**Pile :** `ndaal-io` (`Disk`, `File`, `Clock`, `SimDisk`, `DeviceDisk`), `ndaal-observe` (métriques), `ndaal-common` (configuration), `proptest`, `criterion`.

**Spécification :** [docs/superpowers/specs/2026-11-01-j02c2-wal-writer-design.md](../specs/2026-11-01-j02c2-wal-writer-design.md), validée le 2026-11-01. En cas de doute, elle fait foi.

## Contraintes globales

- **Constantes et défauts :**
  - `FRAME_HEADER_LEN` = 44, `MAX_FRAGMENT` = 1 Mio, `MAX_FLUSH` = 2 Mio, page de 4 096 octets ;
  - borne du tampon en attente : 2 × `MAX_FLUSH` ;
  - configuration : `durability.group_commit_max_bytes` = 256 Kio, `durability.group_commit_max_delay` = 200 µs, `durability.async_flush_interval` = 100 ms, `wal.file_size` = 64 Mio.
- **Graine des CRC** : `recycle_epoch` (u64, petit-boutiste), puis `file_no` (u64, petit-boutiste), placés devant les données couvertes. Masque LevelDB.
- **Version de format : 1.** Le fichier `v1.wal` et le corpus `wal_reader` sont régénérés une seule fois, dans la tâche 1.
- **Règles du code :**
  - aucun réessai de `sync_data` ; après une erreur d'E/S, l'écrivain passe en `Failed` pour de bon ;
  - aucune E/S ni horloge hors des traits (ADR-017) ; aucune `panic!` sur des octets lus ;
  - fichiers de 400 lignes au plus, ASCII seulement, test d'abord, mutation quand un test passe du premier coup.

## Points à surveiller en revue

1. **Le dernier `append` avant un vidage en cours** doit être couvert par le vidage *suivant*, jamais perdu entre les deux tampons. Testé à la tâche 3.
2. **Le passage d'un fichier au suivant pendant un vidage** : la trame qui ne tient plus va dans le fichier suivant, la fin du fichier courant est remplie par `PADDING`, et aucune position durable ne recule. Testé à la tâche 4.
3. **L'arrêt au milieu d'un recyclage** (après la réécriture de l'en-tête, avant le renommage) laisse un `free-*` réutilisable, jamais un fichier numéroté invalide. Testé à la tâche 4.
4. **Un `durable()` attendu après un `Failed`** se termine par une erreur, jamais en attente infinie. Testé à la tâche 3.
5. **`Async` sans aucun autre ajout** finit quand même sur le disque dans les 100 ms (minuteur). Testé à la tâche 5.

### Tâche 3 : `WalWriter` sur un fichier (ajout, vidage, durabilité, erreurs)

**Fichiers :**
- créer `crates/ndaal-wal/src/writer/{mod.rs, buffer.rs, flusher.rs, metrics.rs}` et `crates/ndaal-wal/tests/writer.rs` ;
- modifier `crates/ndaal-wal/Cargo.toml` (`ndaal-io`, `ndaal-observe`, `tokio` « rt ») ;
- `crates/ndaal-io/src/disk.rs`, `real/pool_disk.rs` et `sim/device_disk.rs`, pour `write_all_sync_at`.

**Interfaces :**
- **Dans `ndaal-io`** : `File::write_all_sync_at(&self, buf, offset) -> io::Result<()>`, qui écrit puis rend durable. Son implémentation par défaut appelle `write_all_at` puis `sync_data` ; `PoolFile` la redéfinit en **un seul travail** du pool (spec, décision 3).
- **`WriterConfig`**, dérivé de `Config` : `{ file_size, group_commit_max_bytes, group_commit_max_delay, async_flush_interval }`.
- **`Position { file_no: u64, offset: u64 }`** : `Ord`, ordonnée par fichier puis par décalage.
- **`WalWriter::open(disk: D, dir: &Path, shard: u16, node: NodeId, config: WriterConfig, clock: C, registry: &Registry) -> Result<(WalWriter<D, C>, Flusher<D, C>), WalError>`.**
  - Dans cette tâche, le répertoire est vide : création du fichier `0` (réservation, en-tête, `sync_data`, `sync_dir`).
  - `WalError` gagne `Io(io::ErrorKind)`, `Busy` et `Failed`.
- **`WalWriter`** :
  - `append(&self, record) -> Result<Position, WalError>` (`Busy` au-delà de la borne) ;
  - `durable(&self, Position) -> impl Future<Output = Result<(), WalError>>` ;
  - `durable_position(&self) -> Option<Position>`.
- **`Flusher::run(self)`** : la boucle de spec §4.2. Elle se termine quand le dernier `WalWriter` est abandonné et que tout est vidé, ou à `Failed`.
- **Métriques de spec §4.3**, étiquette `shard`.

- [ ] **Tests d'abord**, en simulation (`Sim`, `SimDisk` derrière un `DeviceDisk`) :
  - `appended_records_read_back` (relecture par `FileReader`) ;
  - `durable_waits_for_the_sync` : `durable()` n'est pas prêt avant la fin du `sync_data` du `SimDevice` ;
  - `append_never_waits_during_a_flush` : `SimDevice` à 1 ms de latence ; pendant le vidage, 1 000 `append` répondent sans faire avancer le temps virtuel, et une tâche voisine progresse ;
  - `flush_rules` (`proptest` avec un `File` qui enregistre les écritures) :
    - jamais deux écritures en même temps ;
    - chaque écriture fait au plus `MAX_FLUSH`, commence sur une page et finit à une frontière de trame suivie de zéros jusqu'à la page ;
    - toute position durable a été couverte par une écriture puis un `sync_data` terminés ;
  - `last_append_before_flush_is_not_lost` (point 1) ;
  - `failed_sync_fails_waiters_and_appends` : `SimDisk::fail_next` sur le fichier ; les attentes reçoivent `Failed`, ainsi que les `append` suivants (point 4) ;
  - `busy_beyond_the_bound`.
- [ ] `cargo test -p ndaal-wal --test writer` réussit ; une mutation (deux vidages autorisés en même temps) fait échouer `flush_rules`.

### Tâche 4 : fichiers, recyclage et reprise

**Fichiers :** `crates/ndaal-wal/src/writer/files.rs` et `crates/ndaal-wal/tests/files.rs`.

**Interfaces (produit) :**
- `WalWriter::release(&self, file_no: u64)` ;
- `open` sur un répertoire existant (spec §5, reprise) : le dernier fichier numéroté, lu jusqu'à la fin `o`, puis effacé de `o` à `min(o + MAX_FLUSH, file_size)`, `sync_data`, et reprise de l'écriture en `o`. `Corrupt` rend `WalError::Corrupt { file_no, offset }` (nouvelle variante) ;
- fichier suivant préparé dès que le fichier courant est à moitié plein ;
- fin de fichier remplie par `PADDING`, jamais 1 à 43 octets libres ;
- fichiers libres `free-<16 chiffres hexadécimaux>.wal`.

- [ ] **Tests d'abord :**
  - `rolls_over_with_padding` : des enregistrements sur 3 fichiers de 4 Mio ; chaque fichier qui n'est pas le dernier se lit jusqu'à sa fin exacte, et tous les enregistrements sont relus dans l'ordre (point 2) ;
  - `fragmented_record_across_files` ;
  - `recycled_file_never_replays_old_records` (T02.09) : `release` du fichier 0, puis rotation jusqu'à le réutiliser ; ses anciennes trames sont encore sur le disque, aucune n'est relue ;
  - `crash_mid_recycle_is_safe` (point 3) : panne entre la réécriture de l'en-tête et le renommage ;
  - `resume_never_resurrects_a_torn_flush` : vidage déchiré (`SimDisk::crash(Random)`), reprise, puis un nouvel enregistrement de même longueur à la position `o` ; relecture : aucune trame non acquittée ;
  - `open_refuses_a_corrupt_log`.
- [ ] `cargo test -p ndaal-wal` réussit.

### Tâche 5 : modes de durabilité et scénario `wal_crash`

**Fichiers :**
- `crates/ndaal-wal/src/writer/mod.rs` (`Durability`, `submit`) et `crates/ndaal-wal/tests/modes.rs` ;
- créer `crates/ndaal-sim/src/wal_crash.rs` ;
- modifier `crates/ndaal-sim/src/{lib.rs, main.rs}` et `crates/ndaal-sim/Cargo.toml`.

**Interfaces (produit) :**
- `pub enum Durability { None, Async, Sync }` ;
- `WalWriter::submit(&self, record, mode) -> impl Future<Output = Result<Option<Position>, WalError>>` : `None` rend `Ok(None)` sans rien écrire ; `Async` répond après l'ajout ; `Sync` répond après `durable` ;
- le `Flusher` vide au plus tard `async_flush_interval` après un ajout `Async` resté seul (point 5) ;
- `pub fn wal_crash(seed: u64) -> WalCrashReport { outcome, acked_sync, lost_sync, lost_async_beyond_window, fingerprint }` et `pub fn wal_crash_result(seed) -> SeedResult` :
  - des tâches écrivent dans les trois modes ;
  - coupure à un instant tiré de la graine, `CrashMode` tiré de la graine ;
  - reprise par `open`, puis relecture complète ;
  - **réussite si aucun `Sync` acquitté n'est perdu, aucun `Async` plus ancien que `async_flush_interval` avant la coupure n'est perdu, et aucun `None` n'est dans le journal.**

- [ ] **Tests d'abord :**
  - `modes_ack_at_the_right_time` ;
  - `lonely_async_reaches_disk_within_the_interval` ;
  - dans `ndaal-sim` :
    - `wal_crash_loses_only_what_modes_allow` (50 graines) ;
    - `wal_crash_is_reproducible` ;
    - `wal_crash_detects_a_lying_sync` : un témoin qui acquitte `Sync` avant `durable` doit échouer.
- [ ] `ndaal-sim sweep` joue `wal_crash` en plus des trois scénarios existants ; la durée de 1 000 graines est consignée dans le registre de travail.
