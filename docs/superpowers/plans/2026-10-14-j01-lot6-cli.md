# J01 lot 6 — Configuration, CLI et internationalisation : plan d'implémentation

> **Pour les agents :** sous-compétence requise : superpowers:executing-plans (ou subagent-driven-development), tâche par tâche.
>
> **Pas d'étape de commit** : le responsable commite sur une branche `j01-lot6-cli` et ouvre une demande de fusion ; la CI fait foi. Le compte rendu donne les commandes git **et le contenu du formulaire de demande de fusion**.

**Objectif :** un binaire `ndaal` configurable par fichier, variables d'environnement et options, dont les messages sont traduits (anglais, français), plus la fermeture de P-31 (non-déterminisme des `HashMap`) avant J02.

**Architecture :** la configuration est une **fonction pure** dans `ndaal-common` (texte TOML, variables d'environnement et surcharges fournis par l'appelant ; aucune E/S, conformément à ADR-017) qui produit une `Config` typée et validée, et la référence de tous les paramètres. `ndaal-cli` lit le fichier par `ndaal-io` et l'environnement, construit l'interface avec `clap` (API de construction, pour des textes traduits à l'exécution), et affiche ses messages par `ndaal-i18n` (Fluent, fichiers intégrés au binaire).

**Pile :** `toml` 1.1 (analyse seulement, sans `serde`), `clap` 4.6, `fluent-bundle` 0.16, `unic-langid` 0.9, `sys-locale` 0.3.

**Spécification :** [CAHIER_DES_TACHES.md](../../../CAHIER_DES_TACHES.md#j01--fondations-du-projet) T01.06, T01.12, T01.23 ; [CAHIER_DES_CHARGES.md](../../../CAHIER_DES_CHARGES.md) EF-GEN-04, EF-GEN-05, EF-GEN-07, ENF-I18N-01 à 06 ; [DECISIONS.md](../../../DECISIONS.md) ADR-017, ADR-029 ; [EXPLOITATION.md §3](../../../EXPLOITATION.md#3-référence-de-configuration) ; [CLAUDE.md](../../../CLAUDE.md) §4.9 ; [POINTS_REPORTES.md](../../../POINTS_REPORTES.md) P-31.

## Contraintes globales

- Priorité (EF-GEN-05) : défauts < fichier TOML < variables `NDAAL_<SECTION>__<CLE>` < options de ligne de commande. Démarrage possible sans fichier (EF-GEN-04).
- Toute donnée de configuration est validée ; une clé inconnue (faute de frappe) est une erreur qui nomme la clé et sa source ; jamais de panique (CLAUDE.md §2).
- Aucun texte destiné à un humain écrit en dur dans la CLI : clés Fluent `cli-*` dans `locales/en/cli.ftl` et `locales/fr/cli.ftl` (CLAUDE.md §4.9) ; journaux, noms de paramètres et sortie machine restent en anglais (ENF-I18N-02).
- Codes de sortie de `ndaal` : `0` succès, `1` erreur d'exécution, `2` erreur d'utilisation ou de configuration.
- Test d'abord ; mutation quand un test passe du premier coup.

## Décisions de périmètre (à valider avec le plan)

1. **Seuls les paramètres utilisés sont implémentés** : `node.data_dir` (défaut `/var/lib/ndaal`), `node.name` (défaut : vide = nom d'hôte, résolu au démarrage), `node.lang` (`auto`, `en`, `fr`), `http.listen` (défaut `127.0.0.1:8080`, utilisé au lot 7), `log.level` (`info`), `log.format` (`json`). Le mécanisme (types, sources, validation, référence générée) est complet ; chaque tâche future ajoute ses paramètres à la table. EXPLOITATION §3 reste la cible et indique quels paramètres sont implémentés.
2. **`toml` sans `serde`** : la table de paramètres décrit les types, l'analyse se fait sur `toml::Table` ; pas de dépendance de sérialisation structurante, donc pas de nouvel ADR.
3. **Sous-commandes non encore construites** (`admin`, `backup`, `restore`, `bench`, `doctor`) : présentes dans l'aide (critère de T01.12), elles répondent « pas encore disponible » (message traduit) avec le code `2`. `ndaal server` charge et valide la configuration, initialise les journaux, puis attend l'arrêt (Ctrl-C) ; le serveur HTTP arrive au lot 7. `ndaal config reference` et `ndaal config show` (configuration effective) sont complets.
4. **Langue du système** lue par `sys-locale` (variables `LC_ALL`/`LC_MESSAGES`/`LANG` sous Unix, préférences de Windows et de macOS), conformément à ENF-I18N-03 ; `--lang` est lu avant la construction de l'interface, puisque l'aide elle-même est traduite.
5. **P-31 : `HashMap` et `HashSet` interdits hors de `ndaal-io`** (clippy `disallowed-types`), remplacés par `BTreeMap`/`BTreeSet` ou par l'alias `ndaal_common::collections::DetMap`/`DetSet` (`BuildHasherDefault<DefaultHasher>` : clés de hachage fixes, ordre de parcours identique d'une exécution à l'autre). Le fichier `crates/ndaal-common/src/collections.rs` rejoint la liste des exemptions de la règle d'hygiène.
6. **Lot 7 (aperçu, pour trancher P-27)** : un serveur minimal `ndaal server` qui expose `/health/live`, `/health/ready` et `/metrics` avec `axum` (cité par ARCHITECTURE §14.3 pour le frontal HTTP), sur un socket ouvert par `ndaal-io` ; une commande `ndaal health` qui interroge le point de santé, utilisée comme `HEALTHCHECK` de l'image Docker (pas besoin d'exposer le port hors du conteneur, ENF-SEC-04 respectée) ; Dockerfile et `compose.yaml`. Le plan du lot 7 détaillera ce choix.

## Points à surveiller en revue

1. **Clé inconnue** dans le fichier, l'environnement ou `--set` (`node.data_dirr`, `NDAAL_NODE__DATADIR`) : erreur nommant la clé et la source. Testé à la tâche 2.
2. **Valeur mal typée** (`http.listen = 8080`, `log.level = "loud"`, taille `12XB`) : erreur, pas de panique. Testé à la tâche 2.
3. **Variables d'environnement étrangères** (`NDAAL_HOME`, sans `__`) : ignorées ou refusées de façon documentée. Testé à la tâche 2.
4. **`--lang` absent, invalide (`--lang xx`) ou langue système inconnue** : repli sur l'anglais, sans erreur. Testé à la tâche 4.
5. **Clé Fluent présente en anglais mais absente en français** : la CI échoue ; à l'exécution, repli sur l'anglais. Testé à la tâche 4.

### Tâche 2 : configuration (T01.06)

**Fichiers :** Créer `crates/ndaal-common/src/config/{mod.rs, params.rs, value.rs}`.

**Interfaces (produit) :**
- `pub struct Sources<'a> { pub file: Option<&'a str>, pub env: Vec<(String, String)>, pub overrides: Vec<(String, String)> }` (surcharges `clé=valeur` de `--set` et des options dédiées comme `--data-dir`).
- `pub fn load(sources: &Sources) -> Result<Config, ConfigError>`.
- `pub struct Config { pub node: NodeConfig, pub http: HttpConfig, pub log: LogConfig }` avec `NodeConfig { data_dir: PathBuf, name: String, lang: LangChoice }`, `HttpConfig { listen: SocketAddr }`, `LogConfig { level: String, format: LogFormatChoice }` ; `LangChoice { Auto, En, Fr }`, `LogFormatChoice { Text, Json }`.
- `pub enum Source { Default, File, Env, CommandLine }` ; `pub struct ConfigError { pub key: String, pub source: Source, pub message: String }` (`thiserror`).
- `pub fn reference() -> String` : une ligne par paramètre, `clé`, type, défaut, variable d'environnement, aide (anglais : sortie machine stable).
- `pub fn render(config: &Config) -> String` : configuration effective au format TOML (pour `ndaal config show`).
- Table des paramètres (`params.rs`) : `struct Param { key: &'static str, kind: Kind, default: &'static str, help: &'static str }` ; `Kind { Path, Text, Choice(&'static [&'static str]), Addr, LogLevel }`. Variable d'environnement : `NDAAL_` + clé en majuscules, `.` remplacé par `__` (`node.data_dir` → `NDAAL_NODE__DATA_DIR`).

- [ ] **Tests d'abord (critère de fin) :** sans aucune source → les défauts ; même clé dans les trois sources → la ligne de commande l'emporte, puis l'environnement, puis le fichier ; clé inconnue dans chaque source → `ConfigError` avec la clé et la source ; valeurs mal typées → erreur ; `NDAAL_HOME` (pas de `__`) → ignorée, `NDAAL_NODE__UNKNOWN` → erreur ; TOML syntaxiquement invalide → erreur `File` ; `reference()` contient chaque paramètre avec son type, son défaut et sa variable ; `render(load(défauts))` relu par `load` redonne la même `Config` (aller-retour).

### Tâche 3 : CLI `ndaal` (T01.12)

**Fichiers :** Modifier `crates/ndaal-cli/src/main.rs` ; Créer `crates/ndaal-cli/src/{cli.rs, commands.rs}`, `crates/ndaal-cli/tests/cli.rs`.

- Interface `clap` (API de construction) : options globales `--config <FICHIER>`, `--lang <en|fr>`, `--set <clé=valeur>` (répétable), `--data-dir <DOSSIER>` ; sous-commandes `server`, `admin`, `backup`, `restore`, `bench`, `config` (`reference`, `show`), `doctor`.
- Le fichier de configuration est lu par `ndaal_io::real::RealDisk` (runtime `tokio` à fil unique) ; l'environnement par `std::env::vars`.
- `ndaal server` : configuration chargée, journaux initialisés (`ndaal-observe`), message de démarrage journalisé, attente de Ctrl-C (`tokio::signal`).

- [ ] **Tests d'abord (`tests/cli.rs`, binaire réel) :** `ndaal --help` liste les sept sous-commandes (critère de fin) ; `ndaal config reference` liste `node.data_dir` ; `ndaal --data-dir /x config show` montre `/x` ; `NDAAL_NODE__DATA_DIR=/y ndaal config show` montre `/y` et `--data-dir` l'emporte ; fichier de configuration avec une clé inconnue → code `2` et message nommant la clé ; `ndaal admin` → code `2`, message « pas encore disponible » ; sous-commande inconnue → code `2`.

### Tâche 4 : internationalisation (T01.23)

**Fichiers :** Créer `locales/en/cli.ftl`, `locales/fr/cli.ftl`, `crates/ndaal-i18n/src/{lib.rs, lang.rs}` ; Modifier `crates/ndaal-cli` (tous les textes passent par `ndaal-i18n`).

**Interfaces (produit) :**
- `pub enum Lang { En, Fr }` ; `pub fn choose(flag: Option<&str>, env: Option<&str>, config: Option<&str>, system: Option<&str>) -> Lang` : première valeur reconnue dans cet ordre (ENF-I18N-03), `auto` passe au suivant, valeur inconnue ignorée, défaut `En`.
- `pub struct Translator` : `fn new(lang: Lang) -> Self` (ressources intégrées par `include_str!`, binaire unique) ; `fn t(&self, key: &str) -> String` et `fn t_args(&self, key: &str, args: &[(&str, FluentValue)]) -> String` ; clé absente dans la langue → texte anglais ; absente partout → la clé elle-même (jamais de panique).
- Aide de `clap` traduite : textes `about`/`help` par clés Fluent, gabarit d'aide (`help_template`) avec les intitulés traduits (« Utilisation », « Commandes », « Options »).

- [ ] **Tests d'abord :** `choose` (table : drapeau prioritaire, `auto`, valeur inconnue, rien → `En`, `fr_FR.UTF-8` système → `Fr`) ; **complétude** : chaque clé de `locales/en/*.ftl` existe dans `locales/fr/*.ftl` et inversement (analyse par `fluent-syntax`), et la CI échoue sinon ; repli : une clé présente seulement en anglais (ressource de test) renvoie le texte anglais ; `ndaal --lang fr --help` contient « Commandes » et la description française de `server` (critère de fin) ; `ndaal --lang xx --help` s'affiche en anglais, sans erreur.
